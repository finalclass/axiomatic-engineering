# Plan: Rozszerzenie obsługi narzędzi dla AI OpenRouter Access

## Cel
Rozszerzyć zestaw narzędzi dostępnych dla agenta AI w trybie OpenRouter, aby lepiej konkurować z funkcjonalnościami Claude Code, z szczególnym uwzględnieniem potrzeb axiomatic-engineering.

## Obecny stan
Obecnie obsługujemy ograniczony zestaw narzędzi zdefiniowanych w `Tools.tool_def` (głównie polecenia systemowe i wyszukiwanie). Narzędzia są wykonywane przez `Tools.execute` i `Web_search.search`.

## Analiza narzędzi z Claude Code (free-code)
Przeanalizowałem kod free-code (https://github.com/paoloanzn/free-code). Obsługuje on ponad 50 narzędzi, w tym:
- Pełne CRUD na plikach
- Git operations
- Wyszukiwanie (glob, grep)
- Testy
- Lint
- Browser automation
- API calls
- Package management
- Process management
- Specyficzne narzędzia dla repl, coordinator mode, itp.

## Brakujące narzędzia dla axiomatic-engineering

### 1. FileReadTool, FileWriteTool, FileEditTool

#### Architektura
```ocaml
(* lib/tools/file_tools.ml *)

type file_operation =
  | Read of { path: string; offset: int option; limit: int option }
  | Write of { path: string; content: string; append: bool }
  | Edit of { path: string; old_string: string; new_string: string }

val execute : base_dir:string -> file_operation -> (string, string) result
```

**Implementacja**: W czystym OCaml (moduł `Sys`, `Unix`, `Stdlib`):
- `Read` - `Stdlib.In_channel.read_all` lub `Unix.openfile` dla dużych plików
- `Write` - `Stdlib.Out_channel.output_string` z `~append` flagą
- `Edit` - `Str.replace` lub niestandardowa logika edycji w miejscu

**Bezpieczeństwo**:
```ocaml
val validate_path : base_dir:string -> path:string -> (string, string) result
(* Walidacja:
   - Path musi być pod base_dir (no ../../etc/passwd)
   - Path nie może być binarny (sprawdź magic bytes)
   - Max rozmiar pliku (np. 10MB dla read)
*)
```

#### Tool Def (OpenRouter format)
```json
{
  "type": "function",
  "function": {
    "name": "file_read",
    "description": "Read contents of a file",
    "parameters": {
      "type": "object",
      "properties": {
        "path": { "type": "string", "description": "Relative path from base_dir" },
        "offset": { "type": "integer", "description": "Start reading from this line" },
        "limit": { "type": "integer", "description": "Max lines to read" }
      },
      "required": ["path"]
    }
  }
}
```

#### Testy
1. **Happy path**: czytanie istniejącego pliku, pisanie nowego, edycja istniejącego
2. **Błędy**: nieistniejący plik, brak uprawnień, plik poza base_dir
3. **Bezpieczeństwo**: 
   - Próba czytania `/etc/passwd` przez `../../etc/passwd`
   - Próba zapisu binarnego (sprawdź czy odrzucone)
   - Próba czytania pliku > 10MB (sprawdź limit)
4. **Edge cases**: pusty plik, plik z jedną linią, Unicode

### 2. BashTool

#### Architektura
Już mamy podstawową implementację w `Tools.execute`. Rozszerzyć o:

```ocaml
(* lib/tools/bash_tool.ml *)

type bash_opts = {
  cwd: string;
  timeout: int option; (* seconds *)
  env: (string * string) list;
  shell: string; (* /bin/sh lub /bin/bash *)
}

val execute : opts:bash_opts -> command:string -> (string, string) result
```

**Implementacja**: `Unix.open_process_full` z timeout przez `Unix.alarm` lub `Unix.kill`

**Bezpieczeństwo**:
```ocaml
val sanitize_command : string -> (string, string) result
(* Zakazane komendy: rm -rf /, mkfs, :(){ :|:& };:, itp. *)
val check_cwd : base_dir:string -> cwd:string -> bool
```

#### Tool Def
```json
{
  "name": "bash",
  "parameters": {
    "command": "string",
    "timeout": "integer (optional, default 60)",
    "cwd": "string (optional, relative to base_dir)"
  }
}
```

#### Testy
1. **Standardowe**: ls, cat, echo, grep
2. **Timeout**: komenda sleep 100 z timeout 1s
3. **Bezpieczeństwo**: próba wykonania `rm -rf /`, `curl | sh`
4. **Środowisko**: zmienne env, cwd

### 3. GlobTool, GrepTool

#### Architektura
```ocaml
(* lib/tools/glob_tool.ml *)

val glob : pattern:string -> base_dir:string -> string list
(* Użyj: Re.Glob lub implementacja własna zgodna z gitignore *)
```

```ocaml
(* lib/tools/grep_tool.ml *)

val grep : 
  pattern:string -> 
  paths:string list -> 
  opts:{ recursive: bool; case_sensitive: bool; max_matches: int option } ->
  string list
(* Użyj: Re.Posix dla regex lub Str.search_forward dla prostych wzorców *)
```

**Implementacja**: 
- `GlobTool` - własna implementacja w OCaml (bez zewnętrznych zależności)
- `GrepTool` - `Re` (ocaml-regex) jeśli już w projekcie, inaczej `Str` + `Unix.find`

**Bezpieczeństwo**: 
- Ogranicz max_results (np. 100 plików dla glob, 1000 matchy dla grep)
- Nie pozwalaj na grep w `/proc` lub `/sys`

#### Testy
1. **Glob**: `*.ml`, `**/*.md`, `src/{a,b}/*.c`
2. **Grep**: prosty string, regex, case insensitive
3. **Bezpieczeństwo**: próba grep w `/etc/shadow`, zbyt wiele wyników
4. **Performance**: duży kod (100k+ linii), mierz czas

### 4. AskUserQuestionTool

#### Architektura

(* lib/tools/question_tool.ml *)

type question_type =
  | Text of { question: string }

  | Confirm of { question: string }

```json

  }
}
```

#### Testy
1. **Interakcja**: mock stdin, sprawdź czy output zawiera odpowiedź
2. **Timeout**: nieudana odpowiedź w czasie
3. **Bezpieczeństwo**: próba injection w pytaniu, zbyt długie pytanie

### 5. WebFetchTool, WebSearchTool

#### Architektura
`WebSearchTool` już mamy. `WebFetchTool` rozszerzyć o:

```ocaml
(* lib/tools/web_fetch_tool.ml *)

val fetch : 
  url:string -> 
  opts:{ 
    method: [`GET | `POST | `PUT | `DELETE]; 
    headers: (string * string) list;
    body: string option;
    timeout: int 
  } ->
  (string, string) result
```

**Implementacja**: Przez `Well.fetch` (już istnieje w codebase)

**Bezpieczeństwo**:
- Whitelist URL (np. tylko http/https, blokuj file://, ftp://)
- Max rozmiar odpowiedzi (np. 5MB)
- Rate limiting (max X requestów na minutę do tego samego hosta)
- Nie pozwalaj na lokalne adresy (127.0.0.1, localhost)

#### Testy
1. **Happy path**: fetch poprawnego URL
2. **Błędy**: 404, timeout, SSL error
3. **Bezpieczeństwo**: próba fetch `file:///etc/passwd`, `http://localhost:22`

```json

{ "name": "git_push", "parameters": { "remote": "origin", "branch": "current", "force": "bool" } }
```

#### Testy
1. **Standardowe**: status, add, commit, push
2. **Błędy**: nie w git repo, merge conflict, brak uprawnień
3. **Bezpieczeństwo**: próba `git push --force origin main`, `git rm -rf .`

## Podsumowanie decyzji implementacyjnych

| Narzędzie | Implementacja | Uzasadnienie |
|-----------|--------------|--------------|
| FileRead/Write/Edit | OCaml (czysty) | Bezpośredni dostęp do FS, pełna kontrola |
| BashTool | OCaml + Unix.process | Już mamy, rozszerzyć o timeout i security |
| Glob/Grep | OCaml (Re/Str) | Szybkie, bez zależności zewnętrznych |
| AskUserQuestion | OCaml (Stdlib) | Proste I/O, bez zależności |
| WebFetch/Search | OCaml (Well.fetch) | Już mamy |
| Git | Zewnętrzny (git) | Złożoność protokołu git, lepiej użyć CLI |
| Test/Lint/Build | Zewnętrzny | Specyficzne dla języków/frameworków |
| Browser | Zewnętrzny (agent-browser) | Złożoność headless browser |
| API | OCaml (Well.fetch) | Już mamy infrastrukturę |
| Package | Zewnętrzny (npm/pip) | Specyficzne dla ekosystemów |
| Process | OCaml (Unix.kill/ps) | Proste operacje systemowe |
| AxiomSpecyfic | OCaml (użyj istniejących modułów) | Integracja z istniejącym kodem |

## Wnioski
Rozszerzenie obsługi narzędzi znacząco zwiększy użyteczność systemu, przybliżając go do funkcjonalności Claude Code. Kluczowe jest zachowanie prostoty i bezpieczeństwa przy dodawaniu nowych narzędzi. Dla axiomatic-engineering najważniejsze są Git operations, weryfikacja i browser automation.
